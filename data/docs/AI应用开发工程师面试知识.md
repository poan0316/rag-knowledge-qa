# AI 应用开发工程师面试知识库

## 一、RAG（检索增强生成）

### 1.1 什么是 RAG
RAG（Retrieval-Augmented Generation，检索增强生成）是一种把「信息检索」与「大语言模型生成」结合的技术架构。核心流程是：先从外部知识库中检索出与用户问题最相关的文档片段，再把这些片段作为上下文拼接到提示词（Prompt）中，交给大语言模型生成最终答案。

RAG 解决的核心问题是：让大语言模型能够回答超出其训练数据范围、或属于私有/实时数据的知识问题，同时提供答案的来源依据。

### 1.2 为什么需要 RAG
- 缓解幻觉：模型基于检索到的真实文档作答，而不是凭空编造。
- 接入私有知识：企业内部的文档、数据库不经过训练也能被问答。
- 知识时效性：知识库更新即可生效，无需重新训练或微调模型。
- 可溯源：答案可以标注引用来源，便于人工核验。
- 成本低：相比微调（Fine-tuning），RAG 无需训练，迭代快。

### 1.3 RAG 完整链路
典型的 RAG 系统由「离线索引」与「在线问答」两阶段组成：
1. 文档解析：把 PDF、Word、Markdown 等转成纯文本。
2. 分块（Chunking）：把长文本切成适合检索的小块。
3. 向量化（Embedding）：把每个分块编码成稠密向量。
4. 写入向量库：向量持久化存储，如 Chroma、FAISS。
5. 检索（Retrieval）：把用户问题向量化，做相似度检索取 top-k。
6. 重排（Rerank，可选）：对候选片段二次精排。
7. 生成（Generation）：把检索结果拼进 prompt，由 LLM 生成带引用的答案。

## 二、文档解析与分块（Chunking）

### 2.1 关键参数
- chunk_size：每个分块的最大长度（字符数或 token 数）。过大则检索粒度粗、噪声多；过小则语义被切断。
- chunk_overlap：相邻分块之间的重叠长度。重叠能避免关键信息刚好被切在边界上而丢失，常见设置为 chunk_size 的 10% 左右。

### 2.2 分块策略
- 固定大小分块：按固定长度切，实现简单，但容易切断语义。
- 递归字符分割（RecursiveCharacterTextSplitter）：按段落、换行、句子等分隔符优先级递归切，最常用。
- 语义分块：借助模型判断语义边界，效果好但实现复杂、成本高。
- 结构感知分块：按文档自带结构（标题、表格、代码块）切，适合结构化文档。

## 三、Embedding（向量化）

### 3.1 什么是 Embedding
Embedding 是把文本映射到高维稠密向量空间的技术。语义相近的文本，其向量在空间中距离更近。Embedding 是连接「自然语言」与「向量检索」的桥梁。

### 3.2 常见 Embedding 模型
- OpenAI text-embedding-3-small / 3-large：云端，效果好。
- BGE 系列（bge-m3、bge-large-zh）：开源，多语言/中文表现强，bge-m3 支持中英混合与长文本。
- nomic-embed-text：开源，多语言，本地部署方便。
- 中文场景优先考虑 bge-m3、bge-large-zh 等中文能力强的模型。

### 3.3 相似度度量
- 余弦相似度（Cosine Similarity）：衡量向量方向一致性，最常用于文本 embedding。
- 欧氏距离（Euclidean Distance）：衡量绝对距离，对向量长度敏感。
- 内积（Dot Product）：向量点积，方向与长度都考虑。

## 四、向量检索（Vector Retrieval）

### 4.1 向量数据库
向量数据库专门存储和检索向量。常见选择：
- Chroma：轻量、易用，适合原型与个人项目。
- FAISS：Meta 开源的向量检索库，性能强，但不是完整数据库。
- Milvus：分布式向量数据库，适合大规模生产。
- pgvector：PostgreSQL 扩展，可与关系数据共存。

### 4.2 相似度检索与 top-k
检索时把用户问题同样向量化，再在向量库中找与问题向量最相似的 k 个分块（top-k）。top-k 越大召回越全但噪声越多，常见取 3~8。

### 4.3 检索质量指标
- 召回率（Recall）：相关文档被检索出来的比例，衡量「找得全不全」。
- 精确率（Precision）：检索结果中相关文档的比例，衡量「找得准不准」。

## 五、重排（Rerank）

### 5.1 为什么需要重排
向量检索是「双塔」（bi-encoder）架构，query 和 document 各自独立编码，速度快但精度有限。重排阶段用精度更高的模型对候选片段重新打分，提升最终排序质量。

### 5.2 bi-encoder 与 cross-encoder
- bi-encoder：query 和 document 分别编码后算相似度，速度快，可离线预存文档向量。
- cross-encoder：query 和 document 成对输入，模型交互计算相关性分数，精度高但慢。
- 常见做法：先向量检索召回较多候选（如 top-k×3），再用 cross-encoder 精排取前 top-k。

## 六、生成与 Prompt

### 6.1 Prompt 组装
把检索到的上下文与用户问题拼进模板，例如：先给出「你只能根据以下上下文回答」的约束，再放上下文，最后放问题，并要求标注来源。约束能显著降低模型编造的概率。

### 6.2 引用溯源
让模型在答案中标注引用了哪条上下文（如编号 [1]、[2]），前端据此展示来源文档与片段。溯源是 RAG 相对纯生成的重要优势。

## 七、评测（Ragas）

### 7.1 核心指标
- Faithfulness（忠实度）：答案中的每句陈述是否都能在检索上下文里找到依据，衡量「有没有幻觉」。
- Answer Relevancy（答案相关性）：答案是否紧扣问题、有无跑题废话。
- Context Precision（上下文精确率）：检索到的上下文里，真正有用的排在多靠前。
- Context Recall（上下文召回率）：标准答案所需的信息是否都被检索出来。

### 7.2 评测集设计
评测集是「问题 + 标准答案 + 参考上下文」的三元组，必须锚定知识库实际文档，覆盖不同章节与题型（事实提取、数值、对比、跨块综合、换词改写）。

## 八、进阶：多智能体（Agent）

### 8.1 什么是 Agent
Agent 是能自主规划、调用工具、根据反馈迭代的大模型应用。相比单次问答，Agent 强调「思考-行动-观察」的循环。

### 8.2 ReAct 模式
ReAct（Reasoning + Acting）让模型交替输出「思考（Thought）→ 行动（Action）→ 观察（Observation）」，通过调用外部工具（搜索、计算、读写文件）完成任务，是多数 Agent 框架的底层范式。

### 8.3 常用框架
- LangChain / LangGraph：LangGraph 用图结构（节点 + 边 + 状态）编排多步骤 Agent 流程。
- CrewAI：面向「角色 + 任务」的多智能体协作框架，适合定义多个专家角色（如研究员、写手、审校）分工完成报告。
